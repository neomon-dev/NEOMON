# Feature Specification: Multi-Agent Analysis & Observation Engine

## 1. Feature Overview
The **Multi-Agent Analysis Engine** orchestrates a collaborative network of specialized autonomous AI agents, each assigned a discrete epistemic role: **Decomposer**, **Literature Synthesizer**, **Methodology Auditor**, **Advocate**, **Skeptic**, and **Adjudication Arbitrator**. The **Agent Laboratory / Observatory** (`/agents`) provides a real-time observation window into agent memory states, execution histories, token utilization, and decision rationales.

## 2. Purpose and Problem Solved
Single-agent AI systems suffer from epistemic myopia: an agent prompted to answer a question naturally seeks out confirmatory evidence, glosses over statistical weaknesses, and reports conclusions with unwarranted certainty. NEOMON's Multi-Agent architecture eliminates this bias through adversarial institutional roles:
- Agents are bound to explicit, opposing scientific objectives.
- Each agent independently inspects the evidentiary corpus.
- The debate loop prevents consensus from forming without explicit empirical justification.
- Researchers can audit the execution trace of every individual agent.

## 3. Where Users Access It
- **Dedicated Route**: `/agents` (Agent Laboratory & Observatory).
- **In-Investigation**: Multi-Agent Intelligence tab on `/investigations/[id]`.
- **System Navigation**: "Agent laboratory" link in the primary navigation sidebar.

## 4. Step-by-Step User Workflow
1. Navigate to `/agents`.
2. Inspect the **Agent Roster**:
   - View all registered autonomous agents, identifiers, descriptions, and operational readiness.
   - Example agents: `decomposer`, `synthesizer`, `methodology_auditor`, `advocate`, `skeptic`, `arbitrator`.
3. Review **Agent Execution History**:
   - Inspect recent agent runs across investigations.
   - Filter by status (`completed`, `running`, `failed`).
   - Click an execution card to inspect the input payload, generated thought chain, and structured output.
4. From `/investigations/[id]`:
   - Click **"▶ Launch Autonomous Analysis & Debate"**.
   - Watch the multi-agent orchestration execute sequentially or concurrently.
   - Inspect real-time agent arguments and rebuttal cards.

## 5. How the Feature Works Internally
1. **Agent Registry**: Agent definitions are stored in the `agents` database table with immutable identifiers.
2. **Task Dispatch**: When an analysis job starts, the `app.analysis.service` creates an `analysis_jobs` entry and dispatches subtasks to the appropriate agent.
3. **Execution Tracking**: Every agent invocation creates an `agent_executions` record capturing `started_at`, `completed_at`, `status`, `error_message`, and the associated `model_configuration_id`.
4. **Structured Protocol**: Agents exchange structured messages adhering to strict Pydantic schemas, avoiding free-form conversational drift.
5. **State Broadcast**: Agent state transitions are emitted to `EventBroker` and broadcast via SSE to the frontend client.

## 6. Relevant Frontend Pages and Components
- `app/agents/page.tsx`: Agent Laboratory and Execution Observatory page.
- `components/agent-observatory.tsx`: Agent card roster, status badges, and execution history modal.
- `app/investigations/[id]/page.tsx`: Multi-Agent Intelligence tab rendering live debate transcripts.

## 7. Relevant Backend Routes and Endpoints
- `GET /api/v1/agents`: Returns all registered agent definitions and operational statuses.
- `GET /api/v1/agents/{agent_id}`: Returns single agent metadata.
- `GET /api/v1/analysis/jobs`: Lists multi-agent analysis jobs for the active workspace.
- `POST /api/v1/analysis/jobs`: Dispatches a new multi-agent analysis job for an investigation.
- `GET /api/v1/analysis/jobs/{job_id}`: Returns execution status, agent outputs, and debate rounds.

## 8. Relevant Services and Agents
- `app.analysis.service`: Job dispatcher and state machine manager.
- `app.agents.decomposer`: Question decomposition specialist.
- `app.agents.synthesizer`: Evidence summarizer and claim formulator.
- `app.agents.methodology_auditor`: Sample size and bias examiner.
- `app.agents.advocate`: Proponent argument builder.
- `app.agents.skeptic`: Counter-evidence and adversarial challenge generator.
- `app.agents.arbitrator`: Objective adjudication judge.

## 9. Database Tables and Relationships
- `agents`: Primary agent definitions (`id`, `identifier`, `name`, `description`).
- `agent_executions`: Individual execution runs (`id`, `investigation_id`, `agent_id`, `model_configuration_id`, `status`, `error_message`, `started_at`, `completed_at`).
- `analysis_jobs`: Parent container for multi-agent analysis runs (`id`, `investigation_id`, `status`, `created_at`).
- `agent_arguments`: Arguments generated by agents during debate rounds.

## 10. Inputs and Outputs
- **Job Creation Request**:
  ```json
  {
    "investigation_id": "UUID",
    "provider_kind": "lmstudio | ollama | openai",
    "model": "model-name",
    "rounds": 2
  }
  ```
- **Job Status Response**:
  Returns job status, list of agent executions, generated arguments, and final consensus report.

## 11. AI Provider Dependencies
- Fully interoperable with local (LM Studio, Ollama) and cloud (OpenAI, Anthropic) models.
- If no AI provider is configured, the engine operates in **Rule-Based Execution Mode**, producing deterministic baseline arguments and mock agent telemetry for testing.

## 12. External API Dependencies
None. Relies on internal agent prompts and indexed database evidence.

## 13. Configuration Requirements
- `NEOMON_ANALYSIS_OVERALL_TIMEOUT_SECONDS`: Maximum runtime for multi-agent jobs (default: 1800s).

## 14. Error Handling and Limitations
- **Individual Agent Failure**: If an agent fails (e.g. LLM timeout), its execution is marked `failed` with the error captured in `error_message`. The parent job logs the failure and attempts retry or graceful completion using remaining agent outputs.
- **Circuit Breaker**: Prevents infinite loops by enforcing a hard cap on debate rounds (maximum 5 rounds).

## 15. Security and Permission Considerations
- Launching multi-agent jobs requires workspace write permissions.
- Execution parameters (prompts, model selection) are validated against strict schemas to prevent prompt injection from untrusted web text.

## 16. Related Features and Dependencies
- **Advocate-Skeptic Debate** (`docs/features/advocate-skeptic.md`): Direct implementation of adversarial agent interaction.
- **Methodology Audit** (`docs/features/methodology-audit.md`): Agent specializing in empirical bias detection.
